# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (lines 72–75) | Returns static `{"status": "ok"}` without testing MongoDB connectivity. When MongoDB is unavailable, it erroneously reports healthy instead of HTTP 503. | Terminate MongoDB or point `MONGO_URI` to an invalid port; `GET /health` continues returning HTTP 200 `{"status": "ok"}`. | Executed `db.command("ping")` within a try/except block; on `PyMongoError` / connection failure, raise `HTTPException(503, "Database unavailable")`. |
| 2 | Global scope (startup) | Startup index creation is completely absent. Without unique indexes on `emp_code` and compound `(emp_code, date)`, duplicate records can be inserted and query performance on 100k docs degrades to collection scans. | Inspect `db.employees.index_information()` and `db.attendance_logs.index_information()`; only the default `_id_` index exists. | Added FastAPI `@asynccontextmanager` lifespan handler creating all necessary indexes (`emp_code` unique, `(emp_code, date)` unique, department/joined_on, date/emp_code, etc.) idempotently. |
| 3 | `create_employee` (lines 78–86) | Race-prone check-then-insert pattern (`find_one` followed by `insert_one`) without handling duplicate key collisions. Under concurrent creation requests, duplicates can be inserted or unhandled 500 errors occur. | Send parallel `POST /employees` requests with identical `emp_code`; multiple documents are created or unhandled 500 crashes occur. | Backed by a MongoDB unique index on `emp_code`, catch `pymongo.errors.DuplicateKeyError` on `insert_one` and return HTTP 409 `{"detail": "Employee with this emp_code already exists"}`. |
| 4 | `EmployeeIn` / `create_employee` (lines 53–61, 78) | Missing validation: `shift_start` and `shift_end` can be identical (contract requires they differ). Regex patterns for `emp_code`, email, and shift times were missing. | `POST /employees` with `shift_start: "09:30"` and `shift_end: "09:30"` returns 201 Created instead of 422 Unprocessable Entity. | Implemented Pydantic model validator enforcing `shift_start != shift_end`, valid date strings for `joined_on`, and regex constraints for `emp_code` (`^EMP\d{4,6}$`), email, and `HH:MM` shifts. |
| 5 | `create_employee` (lines 81–85) | Sets `created_at` to a naive `datetime.now()` and returns raw datetime or ISO string instead of integer epoch milliseconds (`EpochMillis`). | `POST /employees` response contains `"created_at": "2026-10-10T..."` string instead of epoch milliseconds integer. | Stored UTC datetime truncated to whole seconds in MongoDB, and serialized `created_at` as integer epoch milliseconds in the API response. |
| 6 | `list_employees` (line 93) | Calculates pagination offset as `skip = page * page_size`. For page 1, `skip = 20`, completely skipping the first 20 records (page 1 is missing!). | `GET /employees?page=1&page_size=20` returns records 21–40 instead of records 1–20. | Fixed offset formula to `skip = (page - 1) * page_size`. |
| 7 | `list_employees` (line 94) | Unfiltered total count: `total = db.employees.count_documents({})` counts the entire collection, completely ignoring any applied `department` filter (violating R10). | `GET /employees?department=Sales` returns `total: 6` even though only 2 employees belong to Sales. | Changed count to `db.employees.count_documents(q)` to reflect the filtered set. |
| 8 | `list_employees` (lines 89, 95) | Missing sorting and query parameter validation: results are not sorted by `emp_code` ascending, and `page`/`page_size` bounds (`page >= 1`, `1 <= page_size <= 100`) are unenforced. | `GET /employees?page=0&page_size=500` is accepted without validation; returned order does not follow ascending `emp_code`. | Added `Query(ge=1)` for `page`, `Query(ge=1, le=100)` for `page_size`, and chained `.sort("emp_code", 1)` to the database cursor. |
| 9 | `compute_late_minutes` (lines 33–37) | Timezone and grace period calculation defects: (a) Naively replaces hour and minute on `punch_in` ignoring IST timezone. (b) For 09:40:01 on a 09:30 shift (elapsed = 601s), `int(601 / 60) = 10`; condition `minutes > 10` evaluates to `False` and returns 0! But R2 specifies 09:40:01 must yield 10. | Call `compute_late_minutes` with punch-in at 09:40:01 IST; returns 0 instead of 10. | Converted instant to IST, compared elapsed seconds `diff_sec > 600`, and returned whole minutes `int(diff_sec // 60)`. |
| 10 | `compute_work_hours` (line 40) | Uses Python built-in `round()`, which applies banker's (round-half-to-even) rounding instead of decimal half-up rounding (violating R4 and R8). | For elapsed seconds 9018 / 3600 = 2.505 hours, `round(2.505, 2)` gives `2.50` (rounds down to even), whereas half-up requires `2.51`. | Replaced with `Decimal(str(int(diff_sec))) / Decimal("3600")` quantized with `ROUND_HALF_UP`. |
| 11 | `compute_overtime` (lines 44–47) | Overnight shift and overtime threshold defects: (a) Assumes shift end is on the same calendar date as `date_str`, breaking overnight shifts where shift end is on the next calendar day. (b) Omits the R3 minimum threshold of 30 minutes; any elapsed minutes > 0 are returned. | Punch-out at 18:45 on an 18:30 shift end yields 15 minutes overtime instead of 0 (since < 30 min minimum). | For overnight shifts, placed shift end on `date + 1 day` (IST), and only counted overtime when elapsed time is `>= 30` minutes, else 0. |
| 12 | `punch_in` (lines 101, 113) | Missing employee handling raises `TypeError`: when `find_one` returns `None`, line 113 accesses `emp["shift_start"]`, causing an unhandled HTTP 500 error instead of 404. | `POST /attendance/punch-in` with `emp_code: "NONEXISTENT"` returns HTTP 500 Internal Server Error. | Added check: `if not emp: raise HTTPException(404, "Employee not found")`. |
| 13 | `punch_in` (lines 104–105) | Check-then-insert race condition: `db.attendance_logs.find_one(...)` followed by `insert_one` allows parallel requests to insert duplicate daily logs. | Send parallel duplicate punch-in requests for the same employee and date; multiple records are inserted. | Enforced unique compound index on `(emp_code, date)` and caught `DuplicateKeyError` to return HTTP 409 `{"detail": "Already punched in for this date"}`. |
| 14 | `punch_in` (lines 102–103) | Attendance date calculation ignores IST and overnight shifts (R1): uses `datetime.fromtimestamp(...)` and `ts.date().isoformat()` using system local time, and fails to assign punch-in before `shift_end` on overnight shifts to the previous day. | Punch-in at 01:00 IST for a 22:00–06:00 overnight shift on 2026-07-07 gets attendance date `2026-07-07` instead of `2026-07-06`. | Implemented R1 IST conversion: for overnight shifts, if IST time < `shift_end`, assign date as previous calendar day `(dt_ist - 1 day)`. |
| 15 | `punch_in` & `list_attendance` (lines 119, 149) | Exposes internal MongoDB ObjectId: injects `"id": str(res.inserted_id)` into the response, violating the OpenAPI schema and DATA_MODEL.md which prohibit internal IDs. | Attendance API response contains `"id": "670..."`, violating schema contract and validation. | Removed `"id"` field generation and ensured MongoDB `_id` is excluded from all API responses. |
| 16 | `list_attendance` (lines 144–147) | Full collection read and in-memory pagination: loads all matching records across the entire collection into Python memory (`docs = list(db.attendance_logs.find(q))`), sorting and slicing in memory. Fails on 100k docs. | High latency and memory consumption when querying large collections; Python heap bloat. | Replaced with database-side cursor pagination: `.sort([("date", -1), ("emp_code", 1)]).skip(...).limit(...)` and `count_documents(q)`. |
| 17 | `list_attendance` (lines 127–128, 145) | Date range validation and sort order: (a) If `date_from > date_to`, no error was raised (contract requires 422). (b) Sort order only sorted by `date` descending, omitting the secondary sort `emp_code` ascending. | `GET /attendance?date_from=2026-07-10&date_to=2026-07-01` returns HTTP 200 instead of 422. | Added validation `if date_from > date_to: raise HTTPException(422, ...)`, and sorted database cursor by `[("date", -1), ("emp_code", 1)]`. |
| 18 | `PunchInIn` / Timestamp validation (line 65) | Lacks strict validation on `punched_at`: accepts second-based timestamps, floats, or booleans without returning HTTP 422. | `POST /attendance/punch-in` with `punched_at: 1783312500` (seconds) or `True` is accepted instead of rejected with 422. | Added strict validator rejecting booleans, floats, seconds (< 100000000000), and values > 4102444800000 with 422. |

Also note anything you looked at and decided was **not** a defect, and why:

1. **Department filter case-sensitivity in `GET /employees`**: The starter uses exact matching on `department`. Investigated whether this should be case-insensitive (e.g. `$regex` with `i`). OpenAPI explicitly specifies `Exact, case-sensitive match.`, confirming that exact case-sensitive matching is intentional and correct.
2. **Client-supplied `emp_code` on employee creation**: Investigated whether the backend should auto-generate employee IDs. OpenAPI and DATA_MODEL.md explicitly specify that `emp_code` is customer-generated and immutable (e.g. `EMP0001`), supplied by the client, and must be enforced unique by the database.
3. **Attendance records addressed by natural key `(emp_code, date)` without a surrogate ID**: Investigated whether attendance records should have an `id` field. Confirmed that attendance records have no ID in the contract and are addressed solely by the natural compound key `(emp_code, date)`.
4. **Missing `history` and `half_day` in sample document 9 (legacy records)**: Investigated whether missing fields in sample document 9 were defects in seed data. Confirmed per DATA_MODEL.md section 5.9 that legacy records legitimately omit these fields, and the API must gracefully treat missing `history` as `[]` and missing `half_day` as `false`.
